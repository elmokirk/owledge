# v0.7.1 Docs Merge Runbook

## Objective

Ship a truthful, adoption-first v0.7.1 release: a new user can understand
Owledge before installing, choose a supported path, verify value, and identify
limits without maintainer interpretation.

## Session start and recovery

Read, in order:

1. `AGENTS.md`
2. `internal/owledge/workpackages/owledge-v1-autonomous-delivery/GOAL.md`
3. `RUN-STATE.yaml` and `BACKLOG.yaml`
4. [v0.7.1 public docs plan](../plans/v0.7.1-public-docs-adoption-plan.md)
5. [v0.7.1 adoption checklist](v0.7.1-public-docs-adoption-checklist.md)
6. the first ready ticket and its gate

Run `python tools/validate_v1_delivery_plan.py` before work. If a previous
session stopped, rerun the active phase gate and resume from its first unchecked
checklist item; do not recreate completed phases.

## MVP cutline

Must ship: product narrative, Installation Hub, how-it-works lifecycle,
automation/ownership truth, skills/runtime classification, adoption presets,
three proof journeys, truthful Owlib/Hermes status, and green release gates.

Defer: Team Hub, remote Git/CI sync, hosted service, Pi.dev adapter, automatic
cross-project synchronization, and any new runtime capability not needed to
document a current supported path.

## Non-blocking strategic add-on

The Add-on Decision Layer discovery track may ingest private feedback and run
multi-model plan sparring, but it does not delay the v0.7.1 release. Treat
external feedback, scores, and model output as candidate evidence; only an
owner-approved conclusion may alter this runbook, its tickets, or public claims.
See `internal/owledge/plans/add-on-decision-layer-discovery-plan.md`.

## Phase 0 - Freeze truthful baseline

Tickets: `OW-071-01`, `OW-071-02`, `OW-071-03`, `OW-071-13`.

- Reconcile current commands, package contents, known failures, footprint, and
  capability maturity with implementation evidence.
- Classify and harden the local HTTP surface before any public server wording.
- Record exact test/command evidence and resolve contradictions first.

QA: `G-071-A-TRUTH` passes. No public-doc implementation begins before this
phase is green.

Checklist:

- [ ] baseline and local HTTP truth complete
- [ ] QA gate passes
- [ ] independent review complete

## Phase 1 - Write narrative and navigation first

Ticket: `OW-071-04`.

- Rewrite README first screen around **Agentic Engineering Context & Planning
  Layer**.
- Explain why, when, benefits, boundaries, non-goals, and lifecycle before any
  install command.
- Route primary questions to one canonical page within two clicks.

QA: five-second comprehension fixture, claim map, links, and docs lint.

Checklist:

- [ ] narrative and docs home complete
- [ ] QA gate passes
- [ ] independent beginner review complete

## Phase 2 - Complete the four parallel documentation lanes

Tickets: `OW-071-10`, `OW-071-11`, `OW-071-12`, `OW-071-14`.

- Installation: executable recipes, three footprint dimensions, writes,
  verification, recovery, uninstall.
- Workflows: lifecycle diagrams, automation/authority matrix, best-practice
  loop, privacy and recovery boundaries.
- Skills/integrations: `owledge-contract` as Principles-only default; exact
  Codex, Claude Code, OpenCode, and Hermes status/recipes.
- Adoption: presets, folder purpose, Global Layer/Owlib/Hub taxonomy, and
  post-v1 Team Hub boundary.

QA: extracted commands on clean fixtures; Mermaid, navigation, host-agent, and
capability-maturity checks. Integrate README/docs conflicts through one owner.

Checklist:

- [ ] installation lane complete
- [ ] workflow lane complete
- [ ] skills/integration lane complete
- [ ] adoption/hub lane complete
- [ ] lane QA passes
- [ ] integration review complete

## Phase 3 - Prove the golden journeys

Ticket: `OW-071-05`.

- 30-second no-write explanation with visible success signal.
- Package-only five-minute scratch journey.
- Fresh-session or second-agent resume journey without chat history.

QA: scripted three-OS smoke, idempotent rerun, expected output, reset, and
clear optional-runtime degradation.

Checklist:

- [ ] all three journeys implemented
- [ ] QA gate passes
- [ ] independent user/agent review complete

## Phase 4 - Compatibility, release candidate, and merge

Tickets: `OW-071-06`, `OW-071-07`, `OW-071-08`, `OW-071-09`.

- Make Owlib current-layout compatible.
- Prove the required Hermes read-only profile; label only what the fixture
  supports.
- Build and inspect release artifacts, run wheel-based install smoke, then
  prepare the owner alignment update.

QA: `G-071-C-COMPAT`, `G-071-RC`, and `G-071-ALIGNMENT` pass from a clean
integration commit. Merge only after explicit owner approval of the alignment
update; never publish or tag from a dirty tracked worktree.

Checklist:

- [ ] compatibility evidence complete
- [ ] release candidate gate passes
- [ ] owner alignment recorded
- [ ] merge-ready clean state confirmed

## Handoff requirement

Before ending a session, update this runbook or the paired adoption checklist
with the active phase, evidence path, failed or passed gate, changed files,
risks, and the first unchecked item. The next agent resumes from that item.
